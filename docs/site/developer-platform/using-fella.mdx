Fella’s default workflow starts with a conversation. Mount a folder when a question needs local information, choose the model for the conversation, and ask in plain language. Open Notebook when you want to organize the work as a persistent Investigation.

## The everyday workflow

<Steps>
  <Step title="Choose a workspace folder">
    Use the workspace switcher in the title bar to mount the folder Fella may inspect. The folder defines the data boundary; the window layout is only a way to view the work.
  </Step>
  <Step title="Connect and choose a model">
    Configure a provider in Settings, then select the model in the composer. Fella uses your provider key and sends it only to the selected service.
  </Step>
  <Step title="Ask in Chat">
    Ask a direct question or continue the conversation. For data-backed answers, Fella chooses among its built-in read-only analysis tools.
  </Step>
  <Step title="Inspect the answer">
    Open the collapsed **How this was analyzed** details for the run trace and checks. Use Notebook for the broader Investigation, including source scope and coverage.
  </Step>
  <Step title="Preserve useful work">
    Create a report from an answer or from Reports. Reports keep authored notes and exact references to saved output revisions.
  </Step>
</Steps>

## Keep the boundary clear

The model directs analysis, but the Rust engine owns source access, SQL and Python execution, result capture, and verification. Workspace tools cannot edit, move, or delete source files. The user can edit the root context file. The selected hosted provider may receive the question, context, and results needed to answer it.

The mounted folder is Fella’s explicit file-access boundary. The workspace switcher in the title bar lets you open or change that folder. The window’s panel arrangement is a separate presentation choice.

## Open and inspect a workspace

1. Choose a folder with the workspace switcher, or drag a folder into the app.
2. Select **Files** in the sidebar and review usable and skipped items.
3. Open a file preview or ask a question in Chat.
4. After changing files, refresh or reindex the workspace before relying on a new result.

Fella scans to a bounded depth, skips hidden paths, does not follow symbolic links, and applies root .fellaignore rules. A root fella.md file is user-authored context and is not ingested as data.

## Keep the workspace boundary clear

Opening a workspace makes its catalog available to built-in tools. It does not send every file to the model. When a question calls for file-derived content, the model can request specific table results or document passages; those requests may be sent to your selected provider.

Source files are read-only to the agent. Fella can create local catalogs, analysis records, saved outputs, and reports in its own application-data directory.

## Source names and folders

Use **Files** to browse folders and select a source. Tabular files become queryable tables with generated names; sheets in a workbook are listed separately. The catalog and small previews help you verify what was loaded, but do not establish that a file covers the requested population or period.

A root .fellaignore file accepts file names and workspace-relative path prefixes, one per line. Glob patterns are not supported.

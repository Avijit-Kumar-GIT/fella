Fella is bring-your-own-key. Provider credentials are configured in **Settings**; the selected model is visible in the Chat composer and can be changed for that conversation.

## Supported providers

| Provider | Connection | Default model in the current source |
| --- | --- | --- |
| OpenAI | API key | gpt-5.6-luna |
| Vercel AI Gateway | API key | openai/gpt-5.6-luna |
| xAI | API key | grok-4.3 |
| Ollama Cloud | API key for its hosted Ollama API | gemma4:31b |
| OpenRouter | API key | openai/gpt-5.6-luna |
| Custom endpoint | API key and OpenAI-compatible API root | Set by you |

Provider defaults are starting values and can change. When the provider exposes a model catalog, Fella can list the models available to your account.

## Connect and select

1. Open **Settings** from the sidebar.
2. Choose a provider and enter its API key.
3. Return to Chat. Use the model name in the composer to search and select an available model.

Changing the model affects the active conversation. Provider credentials are stored at the app level. The optional consistency check, when triggered by a warning, uses the selected provider and model as well.

The legacy slash commands are still available: use /login to connect or switch provider credentials and /model to list or change a model. The desktop controls are the recommended path.

## Custom endpoint

Choose the custom provider and enter an OpenAI-compatible base URL and model ID in Settings. It uses the OpenAI chat-completions wire format. Do not paste API keys into ordinary questions or commit them to a repository.

## Provider and data boundaries

The selected provider receives model requests for the conversation. Requests may include the prompt, relevant conversation and workspace context, tool schemas, and requested results such as document excerpts or table rows. Fella does not upload the entire folder as a single file, but file-derived content can leave the device when used in an answer.

Fella currently uses one selected model for a conversation. It does not automatically route different Investigation steps to separate models. The Rust engine executes analytics and verification independently of the selected provider.

Document search is local and does not require an embeddings endpoint. For credential storage and data retention, read [Privacy and security](/developer-platform/using-fella/privacy).

<Warning>
  Provider logging, retention, and training practices are controlled by that provider. Review its terms before using sensitive files.
</Warning>

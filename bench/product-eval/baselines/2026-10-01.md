# Pre-change product smoke baseline — 2026-10-01

This records the first pre-runtime-change snapshot for the product roadmap.
It is a small smoke baseline, not a representative estimate of product
quality. Runtime behavior was not changed during these runs.

## Run conditions

- Baseline source revision: `c9ca8c1` (`feat/eval-replay-refs`).
- Model/provider: `openai/gpt-5.6-luna` via the configured OpenAI credentials.
- Evaluator: `cargo run --release --locked --features eval --example agent_eval`.
- Fella used its current prompt/tools; `bare` used the same model without the
  Fella prompt or tools. The no-workspace Fella condition used a fresh engine
  with no mounted folder. The benchmark used a private temporary copy of local
  app data/credentials; the live app database and credentials were not changed
  or included here.
- Filesystem and chart tasks used the existing synthetic benchmark fixtures.
  Each of those tasks ran once. General-knowledge tasks ran three times in
  each condition. Outputs were reviewed against the intended behavior; the
  general-knowledge grader is phrase-based and is only a smoke screen.
- Case-set SHA-256:
  - General knowledge: `4fa2cf2e3b7c10aefce55dc550fa98ebb696f0f9b5d3cbc69440c28431d53d4b`
  - FQA-Bench: `1915e827f8f70957ad8b4501ecf33e0a850015b3ff53bafdfbdc4a66d405b259`
  - Visualization: `4f30952c4802f6a8ebb6ef91c514408e3841008ad977f32bac0824898903dd13`

**Grader-history caveat:** the general-knowledge phrase criteria were
broadened after exploratory model answers had already been seen. The final
3/3 Fella and 3/3 bare majority results below use those revised criteria.
They are post-hoc exploratory results, not an unbiased or pre-registered
baseline. Retain the initial observed misses for audit; do not use these
scores as a clean before/after comparison.

## What this baseline does and does not establish

- The current no-workspace path can answer a few ordinary stable questions,
  despite restrictive surrounding prompt language. This does not yet establish
  broad general-knowledge or research quality.
- Straightforward single-table calculations and two basic chart forms worked
  on these fixtures. The multi-file comparison failure is a concrete baseline
  gap in orchestration, not a reason to tailor runtime logic to this one case.
- Web research is **not implemented** in the current toolset; no web score is
  reported. This pre-change snapshot's forecast instruction discouraged
  estimates. The post-change forecast smoke is recorded in the product-eval
  ledger; its unchanged refusal test failed and the trace showed semantic
  verification errors. Hybrid local-plus-web questions are not runnable until
  both routes exist.
- No statistical claim should be made from one run of each file/chart task or
  three seed general-knowledge questions. Expand coverage by capability family
  and repeat runs before comparing versions. Keep the task set fixed for a
  before/after comparison and review grader misses independently.

## Reproduction

From `src-tauri/`, use a private `AGENT_EVAL_DATA_DIR` containing the required
local auth/config copy. Do not point it at the live app data directory. The
general-knowledge pair is documented in the parent README. The sampled file
and chart runs were:

```bash
AGENT_EVAL_DATA_DIR=/tmp/fella-eval cargo run --release --locked --features eval --example agent_eval -- bench \
  --dir ../bench/folder-qa --only "fqa-fin-rent-2024,fqa-read-avg-rating,fqa-mf-rent-vs-budget" \
  --harness fella --iters 1 --models "openai/gpt-5.6-luna"

AGENT_EVAL_DATA_DIR=/tmp/fella-eval cargo run --release --locked --features eval --example agent_eval -- bench \
  --dir ../bench/visualization --only "viz-category-bar,viz-monthly-auto-line" \
  --harness fella --iters 1 --models "openai/gpt-5.6-luna"
```

The eval JSON artifacts from this run were kept in an isolated temporary
directory rather than checked in. Re-run to produce fresh raw artifacts; do
not interpret regenerated model wording as a byte-for-byte fixture.
